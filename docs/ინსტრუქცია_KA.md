# ASIX-ის ბაზის სრული SQL ექსპორტი — მოკლე ინსტრუქცია

ეს პაკეტი შეიცავს ASIX-ის მიმდინარე ცოცხალი ბაზიდან სრული აპლიკაციური SQL-ის, TypeScript ტიპების, Edge Function-ების და ისტორიის ამოსაღებ ექსპორტერს. **ამ ZIP-ში ჯერ არ არის ცოცხალი ბაზის საბოლოო `schema.sql`** — ის უნდა შეიქმნას შენი უფლებამოსილი კომპიუტერიდან, რადგან Supabase CLI-ს სჭირდება პირდაპირი წვდომა ბაზაზე.

## Windows-ზე გაშვება

1. ჩამოტვირთე და ამოარქივე Stage20 ZIP.
2. დააყენე ოფიციალური Supabase CLI v3 ან უფრო ახალი და Docker Desktop.
3. გახსენი PowerShell პაკეტის საქაღალდეში და ერთხელ გაუშვი `supabase login`.
4. გაუშვი `scripts\START_EXPORT_WINDOWS.bat`.
5. თუ CLI მოითხოვს მონაცემთა ბაზის პაროლს, შეიყვანე მხოლოდ შენს კომპიუტერში. პაროლი ჩატში ან ფაილში არ ჩაწერო.
6. წარმატებისას შეიქმნება `handover-output-თარიღი` საქაღალდე და მის გვერდით ZIP.
7. მიღებული ZIP ატვირთე ამ ჩატში. მას შევამოწმებ და საბოლოო კაზინოს პაკეტად დავაკომპლექტებ.

## რა იქნება საბოლოო ექსპორტში

- `database/schema.sql` — მიმდინარე `public` და `asix_internal` სქემების სრული SQL: ცხრილები, სვეტები, constraints, indexes, views, ფუნქციები, triggers, RLS policies და grants.
- `database/database.types.ts` — ცოცხალი ბაზიდან ზუსტად გენერირებული TypeScript ტიპები.
- `database/migration-history.txt` — 128 მიგრაციის ვერსიისა და სახელის სია. ეს არ არის 128 ისტორიული SQL ფაილის ასლი; აღდგენის საწყისი წერტილია ერთი მიმდინარე schema snapshot.
- `edge-functions/` — Supabase-ზე ამჟამად გაშვებული Edge Function-ების კოდი.
- `frontend/` — ASIX-ის HTML და უსაფრთხო კონფიგურაციის შაბლონი.
- `sql-reference/`, `docs/`, `metadata/` — საწყისი კონფიგურაცია, შემოწმებები და კაზინოს აღდგენის ინსტრუქციები.

## ფინანსური წესი

ASIX-ის საკომისიო არის მთლიანი Entry Fee-ის **5%**; დარჩენილი **95% სრულად შედის საპრიზო ფონდში დარიგების დაწყებისთანავე**. ეტაპობრივი ზრდა და დამატებითი რეზერვი ამ წესში არ გამოიყენება.

## ცოცხალი მოთამაშეების მონაცემები

ნაგულისხმევი ექსპორტი იღებს სტრუქტურასა და კოდს, მაგრამ არა მოთამაშეების პირად მონაცემებს, საფულეებსა და ტრანზაქციებს. სურვილის შემთხვევაში ექსპორტერს აქვს ცალკე `--include-live-data` / `-IncludeLiveData` რეჟიმი, რომელიც მოითხოვს სპეციალურ დადასტურებას და ქმნის ცალკე მგრძნობიარე SQL ფაილს; ის ჩვეულებრივ ZIP-ში არ იდება. ეს ფაილი კაზინოს გადაეცეს მხოლოდ სათანადო უფლებამოსილების, სამართლებრივი საფუძვლისა და დაშიფრული არხის არსებობისას.

Supabase Auth-ის მომხმარებლები, პაროლები, პროექტის გასაღებები, Edge Function-ის საიდუმლო მნიშვნელობები და Storage ობიექტების ბინარული ფაილები ამ ექსპორტში არ შედის — ისინი კაზინოს ახალ Supabase პროექტში ცალკე უნდა შეიქმნას/გადაიტანოს.

**არ გაუზიარო ChatGPT-ს ან კაზინოს საერთო არქივს:** database password, service-role key, JWT signing key ან Edge Function-ის secret value.
